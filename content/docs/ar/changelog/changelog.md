# سجل التغييرات

## نوفمبر 2026

### تصميم جديد

- واجهة جديدة للموقع ولوحة التحكم، بهوية بصرية وشعار محدّثين.
- توثيق جديد بالكامل باللغتين العربية والإنجليزية، يعكس سلوك المنصة الفعلي.

### مفاتيح API في الترويسة

- الطريقة المعتمدة لإرسال مفتاح API أصبحت الترويسة: `X-API-Key: <key>` أو `Authorization: Bearer <key>`.
- إرسال المفتاح في الرابط (`?api_key=` أو `?key=`) أو في جسم الطلب **مُهمَل**. ما زال يعمل مؤقتًا للتثبيتات الحالية، وقد يُعطَّل لاحقًا. راجع [المصادقة](/docs/api/authentication).
- المفاتيح المسمّاة تُخزَّن مُجزّأة ولا تظهر إلا مرة واحدة عند إنشائها.
- المفتاح الافتراضي للحساب لم يعد يُحمَّل تلقائيًا في المتصفح، ويُعرض لصاحب الحساب فقط عند الطلب.

**ما المطلوب منك:** إذا كان لديك تكامل يضع المفتاح في الرابط (مثل إعدادات قديمة لـ WHMCS أو Digits أو Wix Automations)، فانقله إلى الترويسة.

### تحسينات أمنية

- تشديد التحقق من الهوية والجلسات ودعوات الفريق، مع انتهاء صلاحية الدعوات بعد 7 أيام.
- عزل أقوى لبيانات كل حساب عن الحسابات الأخرى.
- حدود معدّل على نقاط الـ API ونقاط تسجيل الدخول.
- التحقق من مصدر الإشعارات الواردة من Meta وWix.
- حماية روابط الـ Webhook الصادرة: تُقبل روابط `https://` العامة فقط.
- التحقق من حد الرسائل الشهري وحالة إلغاء الاشتراك والحظر قبل الإرسال من القنوات الرئيسية.

### إضافة WordPress ووحدة WHMCS

- أُعيدت كتابة إضافة WordPress/WooCommerce ووحدة WHMCS بالكامل، وتُرسل المفتاح في الترويسة.
- إعداد مبسّط: لصق المفتاح، واختبار الاتصال، واختيار الرقم، وتفعيل الأحداث، وتخصيص نصوص الرسائل بمتغيرات الدمج.
- التنزيل من **Integrations ← Modules**. راجع [WordPress](/docs/integrations/wordpress) و[WHMCS](/docs/integrations/whmcs).

### الرسائل خارج نافذة الـ 24 ساعة

- `POST /api/v1/send` لم يعد يرسل قالب الإشعار العام خارج النافذة؛ يرسل القالب الذي تحدّده (أو قالب التسويق الافتراضي مع نص رسالتك)، أو يعيد `422` مع شرح واضح لسبب الفشل. راجع [نافذة الـ 24 ساعة](/docs/getting-started/messaging-window).
- على أرقام Cloud API تُرسل رموز التحقق دائمًا عبر قالب Authentication.
